# 言い換えの判定基準と、実例集

実例はすべて、**実際に公開した記事から拾ったもの**です。同じ書き手の記事の中に、良い例と悪い例の両方があります。

## 判定の基準

**その用語が「何をするものか」が書かれているか。** これだけです。

| | 説明になっている | なっていない |
|---|---|---|
| 略語 | **機能で言い換える** | アルファベットを伸ばす |
| カタカナ語 | **機能で言い換える** | 別のカタカナに置き換える |
| 業界語 | **読者の業務の言葉に置き換える** | 定義文を貼る |

## ✅ 良い例（実記事より）

| 用語 | 書き方 | なぜ良いか |
|---|---|---|
| LLM | `LLM（パソコンの中だけで動くAI）` | **どこで動くか**が分かる。読者の関心（社外に出るのか）に答えている |
| Claude | `Claude（クラウド上のAI）` | 上と対になっていて、違いが分かる |
| TUI | `TUI（画面の枠やロゴ）` | **目に見えるもの**で説明している |
| PMP | `PMP（プロジェクトマネジメントの国際資格）` | 何の資格かが分かる |
| GAS | 「**Googleの無料プログラム**」 | 誰の・いくらの・何か、が1行で分かる |

## ⚠️ 展開しただけの例（実記事より・要改善）

| 用語 | 書き方 | 何が足りないか |
|---|---|---|
| GAS | `GAS（Google Apps Script）` | **伸ばしただけ。** 読者は「Apps Script」も知らない |
| Substack | `Substack（サブスタック）` | **カタカナにしただけ。** 何ができる場所か不明 |
| Obsidian | `Obsidian（私のメモアプリ）` | 惜しい。「私の」が主語で、読者には関係がない |

> **同じ書き手でも、記事によってぶれます。** だから点検が要ります。

## よく出る用語と、言い換えの方向

そのまま貼らず、**原稿の文脈に合わせて**書き換えてください。

| 用語 | 方向 |
|---|---|
| API | 「システム同士をつなぐ窓口」「別のソフトから操作するための入口」 |
| RAG | 「社内の資料を検索して、その内容をもとにAIが答える仕組み」 |
| リードタイム | 「受けてから終わるまでの時間」 |
| 属人化 | 「その人しか分からない状態」 |
| KPI | 「目標に近づいているかを見る数字」 |
| 一次解決率 | 「最初のやり取りだけで片づいた割合」 |
| 直行率 | 「手戻りなく一度で通った割合」 |
| MTTR | 「止まってから直るまでの平均時間」 |
| オンプレ | 「自社の中に置いたサーバー」 |
| デプロイ | 「作ったものを本番で動く状態にすること」 |
| リポジトリ | 「プログラムの保管場所」 |
| フロントマター | 「ファイルの先頭に書く設定部分」 |
| symlink | 「本体は1か所に置いて、別の場所からたどれるようにする仕組み」 |

## 説明が要らないもの

読者を固定したうえで、**その読者が日常的に使う語**は説明しません。

- 事業者向けの記事での「見積」「請求書」「棚卸し」
- 開発者向けの記事での「Git」「CLI」「JSON」
- 誰にとっても一般的な「Excel」「メール」「フォルダ」

**説明を足しすぎると、逆に読みにくくなります。** 説明の数ではなく、**読者が止まる箇所を減らすこと**が目的です。

## 判定に迷ったときの問い

> **その読者が、その語を業務で口に出したことがあるか。**

あるなら説明不要。無いなら説明が要ります。
